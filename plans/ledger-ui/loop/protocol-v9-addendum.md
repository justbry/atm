# Protocol v9 addendum: the owner's goal of 2026-11-06

Replaces GOAL.md section 7 (done) and amends protocol-v8 §9 and §10. Everything else in v8 stands.

1. **Target.** The mockup on atm `dev` at the time a slice is built. It moves: before every panel, rebase onto `dev`, re-sync the slice to the current mockup and reshoot the mockup side. The target freezes only when the owner says the disclosure-v2 PR (global "View as" dropdown, period selector, audience gating on every tab) merged.
2. **Two scores.** Similarity is v8's rubric (screens side by side at 1100, 728 and 390 px, light and dark). Feature parity is a sixth reviewer axis, scored 1 to 10 against a checklist generated from the mockup (`L/parity-checklist.md`: every tab, control, menu item, state, audience, empty and error state, keyboard path).
3. **Parity gate (objective).** `plans/ledger-ui/design/smoke.mjs` is the mockup's executable feature spec. `packages/ledger-ui/test/parity/` runs the same check code against the built UI through a thin adapter: `map.json` (mockup selector to UI selector, and mockup internals to UI functions) and `checks.json` (check id to slice, status `pass | pending | na`, the UI selector used, and for `na` a written reason). Gate R in `gates/run.ts`: every check owned by a slice up to the current one passes or is `na` with a reason a panel accepted. The table is regenerated from the current smoke.mjs before each panel, and new checks are assigned to slices.
4. **Pass.** All three reviewers at 9 or more on similarity and on parity, gate R at 100 percent for the slice, no blockers, all other gates green. Merge when green as before (owner: "auto fix, merge when green").
5. **Scope.** The whole UI on fixtures, S0 to S7 plus the deltas: S0b (View as, period selector), S1b (audiences and the shared disclosure object, not our own rule engine where buzz-school's KPI demo already has one), S2 Bookings, S3 Plans (Edit, Preview, Code YAML), S4 Members (roles, Books chip, ⋯ menu, drawer), S5 Ledger, Reports (donors, CSV) and Promos, S6 member portal (Invoices, history, CSV, School books card, Family tab, themes, embed), S7 Settings (School books disclosure table), audience gating on every tab. S8 stays blocked with its reason and is outside the 9/10.
6. **Final.** After the last slice passes, one whole-app panel (three models, full mockup against full UI, every tab x audience x width x theme). Its two scores and the PR stack list go to the owner.
7. **State.** `state.json` keeps per-slice similarity and parity scores and the parity table's path and counts.
